# Урок 10 «Музыкальный регулятор»: контракт модулей

## Что строим

Интерактивную страницу для занятия кружка робототехники. Занятие завтра, 2 академических часа.
Ученики: 7–9 классы и один ученик 6 класса. Страницу учитель показывает через проектор, ученики могут открыть её сами.
Файл должен работать без интернета: всё собирается в один HTML.

Строка из учебного плана (менять формулировки шагов нельзя):

- Тема: Масштабирование данных (`map()`). Цель: освоить математическое преобразование диапазонов датчиков через `map()`.
- Проект: Музыкальный регулятор.
- Шаг 1. Считать данные с потенциометра и перевести диапазон 0–1023 в 0–255 через `map()`.
- Шаг 2. Управлять яркостью RGB-светодиода с помощью потенциометра.
- Шаг 3. Перевести данные с потенциометра в частоту звука (200–2000 Гц) для buzzer.
- Шаг 4. Добавить кнопку смены режима работы потенциометра (Управление светом / Управление звуком).

Требования учителя:

1. 2D-схема подключения как в Tinkercad.
2. 3D-визуализация.
3. Тема объяснена понятно: в классе разброс от 6 до 9 класса.
4. Примеры, где это используется и где может применяться.
5. Схема с кодом обязательно. Код и схему можно отдельно развернуть на весь экран.
6. В самом конце: задачки, тренажёр кода, визуальные задания.

## Факты, которые нельзя исказить

Проверено по исходникам ядра Arduino AVR и официальной документации.

- `map()`: `(x - in_min) * (out_max - out_min) / (in_max - in_min) + out_min`, все значения `long`.
- Дробная часть отбрасывается, округления нет. `map(512, 0, 1023, 0, 255)` = 127, а не 128.
- `map()` не ограничивает результат: `map(1200, 0, 1023, 0, 255)` = 299. Для ограничения есть `constrain()`.
- Нижняя граница может быть больше верхней: `map(x, 0, 1023, 255, 0)` переворачивает шкалу. Отрицательные числа работают.
- `analogRead()`: 0–1023 (10 бит, 1024 значения). `analogWrite()`: 0–255 (8 бит, 256 значений), только на пинах с `~`: 3, 5, 6, 9, 10, 11.
- На Uno R3 `analogWrite(pin, 300)` не даёт ошибки: регистр ШИМ 8-битный, лишние биты теряются, остаётся `300 & 255` = 44. Без `map()` яркость при повороте ручки четыре раза проходит 0→255 (пила). Функция `MapLab.pwmBits()`.
- `tone()` занимает таймер 2 и мешает ШИМ на пинах 3 и 11. Поэтому светодиод на пинах 5, 6, 9. Минимальная частота `tone()` 31 Гц. Одновременно звучит только один тон. Повторный вызов на том же пине просто меняет частоту.
- `tone()` меняет высоту звука только у пассивного buzzer. Активный пищит одной нотой.
- Кнопка подключена с `INPUT_PULLUP`: не нажата = HIGH, нажата = LOW.
- Если RGB-светодиод с общим анодом: общая ножка идёт на 5V, а яркость получается наоборот (`255 - brightness`).
- Напряжение на A0: `pot * 5 / 1023` В. `MapLab.sim()` отдаёт его как `volts`.

Контрольные числа: 0→0, 256→63, 512→127, 767→191, 1023→255; частота 0→200, 512→1100, 1023→2000.

## Общие правила кода

- Чистый JS без сборки и без библиотек. Каждый файл обёрнут в IIFE и пишет в `window.MapLab`.
- Поддержка школьных компьютеров: Chrome 90+, Firefox 90+. Нельзя: `:has()`, вложенный CSS, container queries, `color-mix`.
- Классы и id с префиксом модуля: `sch-`, `s3d-`, `wb-`, `ex-`, `use-`, `pr-`. Глобальные стили не трогаем.
- Цвета только через токены из `base.css`. Исключения: физические цвета деталей на схеме и в 3D (`CIRCUIT.WIRE_COLORS`, плата, макетка) и свечение светодиода.
- Обе темы работают: `--bg --surface --surface-2 --ink --ink-2 --line`. Сцена со схемой всегда светлая (`--stage`), код всегда тёмный (`--code-*`).
- Значение датчика и всё, что к нему относится: `--in`. Результат и устройство: `--out`. Других акцентов нет. Зелёный и красный только для верно/неверно.
- Всё, что читается, видно сразу без скролла-анимаций и без `opacity: 0`.
- Страница не скроллится вбок на 400 px. Широкое содержимое живёт в своём `overflow-x: auto`.
- Управление с клавиатуры, видимый фокус, подписи `aria-label` на русском, у всех полей стабильный `id`.
- `prefers-reduced-motion` соблюдается (`MapLab.reducedMotion()`).
- `localStorage` только через `MapLab.store`.
- `alert/confirm/prompt` и `window.print` не работают. Нет `<a download>`. Нет эмодзи: ни в тексте, ни в маркерах.
- Шрифты: `--font-display` только для крупных заголовков и больших чисел. Тело `--font-body`. Код и числа в данных `--font-mono`.

## Правила текста

Пишем для школьника, на «ты», по-русски, живо и коротко. Одна мысль в предложении.

- Базовое объяснение понимает ученик 6 класса: он знает дроби, проценты и пропорции. Линейная функция, биты и `long` только в блоках с меткой `.level` «7–9 класс» или «8–9 класс».
- Термины везде одинаковые: потенциометр, RGB-светодиод, buzzer, макетная плата (макетка), рейка, пин, шкала, диапазон, частота, яркость.
- Без канцелярита и англицизмов там, где есть обычное слово. Без шаблонов «важно отметить», «не просто X, а Y», «давайте разберёмся», «это не X, а Y». Тире только там, где оно нужно по правилам русского языка.
- Никаких выдуманных фактов и статистики. Если пример упрощён, так и напиши.
- Подписи кнопок говорят, что произойдёт: «Проверить», «Следующая задача», «Показать решение».

## Модули

### schematic: 2D-схема в стиле Tinkercad

`MapLab.createSchematic(host, opts)` рисует SVG. Всё положение берётся из `CIRCUIT`: `pos()`, `wirePoints()`, `colX()`, `rowY()`, `strip()`, `node()`. Координаты отверстий руками не задаём. `viewBox` равен `CIRCUIT.view` (мм).

```js
const view = MapLab.createSchematic(host, {
  step: 0,          // показать всё, у чего step <= этого значения
  live: true,       // слушать MapLab.on: ручка, светодиод, buzzer, кнопка
  interactive: true,// ручку можно крутить мышью и пальцем, кнопку нажимать
  labels: true,     // подписи значений рядом с деталями
  wires: null,      // заменить список проводов (задание «найди ошибку»)
  parts: null,      // заменить детали
  onPick: null,     // (id, kind) клик по проводу или детали
});
view.setStep(n); view.setUpto(i|null); view.highlight(id|null);
view.mark(id, 'ok'|'bad'|null); view.setLabels(bool); view.destroy(); view.svg;
```

`setUpto(i)`: показать только `CIRCUIT.ITEMS` с индексом ≤ i (пошаговая сборка), `null` — всё для текущего шага. `highlight(id)`: выделить элемент, остальное приглушить. Детали и провода более ранних шагов остаются на месте, новые детали шага слегка отмечены.

Вид. Открой в памяти Tinkercad Circuits: плоские, аккуратные, почти фотографические компоненты на белом столе.

- Arduino Uno R3: бирюзовая плата с вырезанным контуром, чёрные гребёнки с пинами в реальных позициях, серебристый USB, чёрное гнездо питания, чип DIP-28, кварц, кнопка reset, светодиоды, надпись `UNO`. Без логотипа Arduino. Подписи пинов из `UNO_LABEL`, как на шелкографии, белым.
- Макетка: светлый корпус с рельефной центральной канавкой, красная и синяя линии реек со значками + и −, отверстия квадратными тёмными точками, номера столбцов (1, 5, 10…30) и буквы рядов слева и справа, рейки группами по пять. Порядок рядов берём из `ROWS_TOPDOWN`, порядок реек из `RAIL_UNITS`: как в Tinkercad, снаружи сверху «−», снаружи снизу «+».
- Потенциометр: ножки в `e2, e4, e6`, корпус над ними (заходит на канавку и верхнюю половину), большая ручка с белой риской. Ручка поворачивается от −135° до +135° для pot 0…1023 по часовой стрелке.
- RGB-светодиод: полупрозрачный купол и четыре ножки, веером к своим отверстиям, катод длиннее. Свечение по `d.led` (белое, радиальное, заметное).
- Резисторы 220 Ом: бежевый корпус, полоски красная, красная, коричневая, золотая. Выводы к отверстиям. Перекидываются через канавку.
- Buzzer: чёрный диск со значком + и отверстием в центре. При `d.tone` расходятся дуги, частота мигания зависит от частоты звука.
- Кнопка: квадратный корпус на четырёх ножках через канавку, цветной колпачок, при нажатии смещается.
- Провода: цвет из `WIRE_COLORS`, скруглённые углы, тонкая светлая обводка, чтобы чёрный читался, металлический наконечник на концах.

Поведение как в Tinkercad:

- Наведение на отверстие макетки подсвечивает всю соединённую полоску (`strip()`) и показывает подсказку с именем отверстия.
- Наведение на провод или деталь: подсказка с `title` и выделение. Наведение на пин Uno: подпись пина и что на нём подключено.
- Ручка: тянем мышью или пальцем (по кругу), колесо мыши, стрелки с клавиатуры (`role="slider"`, `aria-valuenow`). Значение идёт через `MapLab.set({pot})`.
- Кнопка: `MapLab.press(true/false)` на нажатие и отпускание, Space/Enter с клавиатуры.
- Подписи `labels`: рядом с A0 значение `pot`, рядом со светодиодом `brightness`, рядом с buzzer частота в Гц. Показываются только когда есть смысл на этом шаге.

Схема должна быть читаемой и в 800 px ширины, и на весь экран. Обновляй только то, что изменилось: `pot` меняется часто.

### scene3d: 3D-сцена на Three.js r128

`THREE` и `THREE.OrbitControls` уже подключены сборщиком (файлы `src/vendor/`). Если их нет или WebGL недоступен, покажи спокойное сообщение и предложи 2D.

```js
const view = MapLab.createScene3D(host, { step: 0 });
view.setStep(n); view.setUpto(i|null); view.highlight(id|null);
view.setCamera('iso'|'top'|'front'|'side'); view.setLabels(bool);
view.resize(); view.destroy();
```

Единственный источник геометрии: `CIRCUIT`. Координаты x, y в мм становятся осями X и Z сцены, ось Y вверх. Размеры настоящие.

- Uno: стеклотекстолит с вырезом, стойки, чёрные гребёнки (высота 8,5 мм), USB, разъём питания, чип, кварц, конденсаторы, кнопка. Шелкография через `CanvasTexture` с теми же подписями `UNO_LABEL`.
- Макетка: корпус высотой 8,5 мм, канавка, текстура с отверстиями и подписями через `CanvasTexture`.
- Детали те же, что в 2D, в тех же отверстиях, в том же масштабе. Ручка потенциометра, купол светодиода с `emissive` и точечным источником, полосатые резисторы, buzzer, кнопка.
- Провода: `TubeGeometry` по дугам через `wirePoints()`, пластик и металлический кончик, входят в отверстия, а не висят рядом. Перемычки дугой над рейками.
- Сцена: светлый стол-коврик, мягкие тени, студийный свет. Чёрные провода должны быть видны.
- Управление: вращение и зум через OrbitControls, отдельные кнопки вида (в workbench), ручку можно крутить мышью прямо в сцене (raycast), кнопку нажимать кликом. Пока тянем ручку, камера стоит на месте.
- Подписи `setLabels(true)`: HTML-метки над деталями (потенциометр, RGB-светодиод, buzzer, кнопка, Arduino Uno, макетка), следуют за проекцией и прячутся за камерой.
- Живое состояние из `MapLab.on`: ручка поворачивается, светодиод светится, у buzzer дрожит мембрана или расходятся кольца, кнопка опускается.
- Появление новых деталей шага: короткое падение на место, если нет `reducedMotion`.
- Рисуем по требованию: кадр только при изменении или движении камеры. Вне экрана и на скрытой вкладке не рисуем. `setPixelRatio(min(dpr, 2))`. Сцена должна идти на слабом школьном компьютере.

### workbench: раздел `#lab`, схема с кодом

`workbench/workbench.html` содержит `<section id="lab" class="section">`. Модуль создаёт `createSchematic` и `createScene3D`, вторую лениво, при первом открытии вкладки 3D.

Состав раздела:

- Заголовок «Часть 3 из 5», формулировка.
- Вкладки шагов 1–4 (`CIRCUIT.STEPS`, `MapLab.set({step})`) и точный текст задачи шага.
- Панель «Схема подключения» (`.panel`): переключатель 2D/3D, «Подписи», кнопки вида для 3D, кнопка `[data-fs]`. Внизу полоса управления: ползунок потенциометра 0–1023, живые значения, на шаге 4 кнопка режима и индикатор «Свет / Звук», на шагах 3–4 кнопка «Включить звук» (`MapLab.set({audio})`, звук только по клику).
- Панель «Код» (`.panel`): имя файла, «Копировать», `[data-fs]`. Номера строк, подсветка `MapLab.highlight`, живые значения из `live` в конце строки, приглушение веток из `dim`. Ниже Serial Monitor, если у шага есть `serial` или `serialOnMode`: строки появляются с шагом `serialMs`, есть «Пауза» и «Очистить», список не растёт бесконечно. В полноэкранном коде тоже есть ползунок потенциометра.
- На широком экране панели стоят рядом, схема шире кода. На узком друг под другом. Высота панелей сопоставима.
- На весь экран разворачивается одна панель, остальное скрыто. Шрифт кода заметно крупнее (читается с последней парты), SVG и canvas занимают всю панель, панель управления остаётся видна, Esc выходит. Проверь и настоящий Fullscreen API, и запасной `.is-max` (в iframe API может быть запрещён).
- Список сборки: `CIRCUIT.ITEMS` текущего шага, строки нумерованы. Клик по строке вызывает `setUpto` и `highlight` в 2D и 3D. Кнопки «Назад», «Дальше», «Показать всё». Перед шагом 1 список деталей `CIRCUIT.BOM`.
- Разбор кода по шагам простыми словами, задание «Проверь себя» для каждого шага (с реальными числами, которые можно получить на этой же странице).
- Блок «Если не работает»: симптом и что сделать. Минимум: светодиод работает наоборот (общий анод), buzzer пищит одной нотой (активный), Serial показывает мусор (скорость 9600), значения скачут сами (A0 не подключён), шкала идёт в обратную сторону (5V и GND на потенциометре перепутаны), кнопка не срабатывает (ножки на одном столбце, подключай по диагонали), почему светодиод не на пинах 3 и 11.
- Примечание: на некоторых макетках буквы рядов идут в обратном порядке, ориентируйся по рисунку и столбцам.

Шаг, положение ручки и режим хранятся только в `MapLab.state`, все виды показывают одно и то же. Смена шага сбрасывает `upto`, а при выходе с шага 4 `soundMode: false`. Клавиши 1–4 не перехватываем, если фокус в поле ввода.

### explain: герой, `#why`, `#how`

`explain/explain.html` содержит `<section id="hero">`, `<section id="why">`, `<section id="how">`.

**Герой** открывает страницу живой демонстрацией, а не картинкой. Заголовок про map() как переводчик между шкалами, одна фраза смысла, метаданные: Урок 10, 2 часа, проект «Музыкальный регулятор». Рядом большие две шкалы (`createRulers`) 0–1023 → 0–255 и светящийся светодиод, который сразу реагирует. Без `100vh`. Лёгкая анимация ползунка при загрузке только если нет `reducedMotion` и пользователь ещё не трогал.

**#why** «Зачем нужен map()». Датчик говорит на шкале 0–1023, светодиод понимает 0–255. Два светодиода рядом и один ползунок: без `map()` (через `pwmBits`) и с `map()`. Маленький график настоящей яркости обоих вариантов, пила и ровная линия, отметка текущего положения. Объяснить, почему так, простыми словами. Для 8–9 класса: 10 бит, 8 бит, откуда 1024 и 256, как `analogWrite` теряет старшие биты.

**#how** «Как работает map()», от простого к сложному, каждый блок с меткой `.level`:

1. Всем. Главная мысль: `map()` сохраняет долю пути. Прошёл половину одной шкалы, значит половину и другой. `map` по-английски карта: на карте всё то же самое, только в другом масштабе. Ещё один бытовой пример с конкретными числами, понятный шестикласснику.
2. Всем. Анатомия вызова `map(значение, откуда_от, откуда_до, куда_от, куда_до)` с цветами входа и выхода.
3. Всем. Лаборатория `#ex-lab`: пять параметров можно менять, готовые наборы (яркость 0–255, частота 200–2000, серво 0–180, проценты 0–100, наоборот 255–0), живая строка кода, шкалы `createRulers`, результат.
4. 7–9 класс. Считаем вручную по шагам для текущих значений лаборатории: сколько прошли, какая это доля, сколько это на новой шкале, прибавляем начало. Через настоящую формулу с настоящими числами. Связь с пропорцией и `y = kx + b`, график `createGraph`.
5. 8–9 класс. Подводные камни с живыми примерами: дробь отбрасывается, выход за пределы и `constrain()`, почему внутри `long`, почему для вольт `map()` не подходит (`pot * 5.0 / 1023`).

### uses: раздел `#uses`

`uses/uses.html` содержит `<section id="uses" class="section section--alt">`. Заголовок «Часть 4 из 5».

**Где это уже работает**: 6 карточек с живым мини-примером. В каждой: откуда число, строка кода с настоящими диапазонами, ползунок, маленькая анимированная SVG-картинка, короткий рассказ. Диапазоны реалистичные, упрощения названы.

1. Сервопривод: `map(pot, 0, 1023, 0, 180)`, рука или шлагбаум поворачивается.
2. Парктроник: `map(cm, 5, 100, 50, 1000)`, расстояние до стены → пауза между писками, машина подъезжает.
3. Автояркость экрана: `map(light, 0, 1023, 20, 255)`, солнце и телефон.
4. Влажность почвы: `map(raw, 850, 350, 0, 100)`, шкала перевёрнута, потому что сухая почва даёт большое число. Сенсор и его числа зависят от модели, нужна калибровка.
5. Джойстик робота: `map(y, 0, 1023, -255, 255)`, отрицательные числа: вперёд, стоп, назад.
6. Терменвокс: `map(cm, 5, 50, 2000, 200)`, рука ближе, звук выше. Связь с нашим проектом.

Карточка не должна быть перегружена. Сетка ровная. Один общий стиль мини-примеров.

**Что можешь собрать сам**: 6 идей проектов для школьника (ночник, метроном, робот-рука, индикатор уровня, цветомузыка, игра на реакцию или свои), для каждой датчик, устройство и строка `map()`. Коротко, списком или компактными строками, не карточками с большими отступами.

### practice: раздел `#practice`, самый конец страницы

`practice/practice.html` содержит `<section id="practice" class="section">`. Заголовок «Часть 5 из 5». В начале файла `practice.js` все данные заданий лежат в `MapLab.PRACTICE`, отдельно от DOM, чтобы `check/check-practice.js` мог проверить каждый ответ через `mapInt` в Node. DOM-код только если есть `document`.

Метки сложности `.level`: «Лёгкое», «Среднее», «Сложное». Общий счёт решённого сохраняется через `MapLab.store`, есть сброс. Неверный ответ не наказывается: подсказка, повтор, «Показать решение» с разбором.

**Блок 1. Задачки на map()**. Генератор с тремя уровнями:

- Лёгкий: красивые числа, считается в уме (0–100 → 0–10, 0–10 → 0–100, половина, четверть).
- Средний: диапазоны Arduino: 0–1023, 0–255, частоты, углы.
- Сложный: ненулевое начало, перевёрнутые диапазоны, отрицательные числа, отбрасывание дроби.

Плюс 6–8 текстовых задач из жизни с готовыми ответами.

**Блок 2. Тренажёр кода**. Обязательные типы:

- Заполни пропуски в настоящем коде. Проверка по смыслу.
- Напиши строку `map()` сам: текстовое поле, разбор `map(...)`, сравнение поведения на нескольких значениях, а не текста. `map(x, 1023, 0, 255, 0)` засчитывается как `map(x, 0, 1023, 0, 255)`. Сообщение об ошибке объясняет, что не так: нет скобки, не те числа, перепутан порядок.
- Найди ошибку: клик по строке. Примеры: `analogWrite` на пине без `~`, забытый `pinMode` кнопки с `INPUT_PULLUP`, `map()` с перепутанными диапазонами, сравнение `=` вместо `==`, `tone` с пином светодиода.
- Расставь строки по порядку: кнопками вверх/вниз и перетаскиванием.
- Итоговые задания на доработку проекта, с показом решения, для самостоятельной работы на плате: тишина на нуле, цвет меняется с частотой, третий режим, перевёрнутая ручка.

Всего не меньше 12 задач.

**Блок 3. Визуальные задания**. Обязательные типы:

- Поставь метку: дана строка `map()` и значение, ученик перетаскивает метку на нижней шкале, проверка с допуском, потом показывается точный ответ.
- Найди ошибку на схеме: настоящая `createSchematic` с подменённым проводом или деталью и `onPick`. Минимум 4 разных поломки: провод A0 не в той строке, 5V и GND поменяны, кнопка подключена двумя проводами к одному столбцу, катод светодиода без GND, резистор не перекинут через канавку.
- Какой график: выбери график для строки `map()` (используй `createGraph` с `showPoint: false`).
- Соедини пары: датчик и его типичный диапазон или `map()` и устройство (клик по паре, работает на телефоне).
- Настрой шкалу: ученик подбирает `out_min`, `out_max` или `in_min`, `in_max`, чтобы стрелка показывала как нужно.

Всего не меньше 10 заданий.

## Как проверять работу

Если в пути к проекту есть пробелы или кириллица, бери пути в кавычки. Скриншоты, временные страницы и сборки клади только в `/tmp/map-shots/`, в папку проекта их не пиши. Сценарии, которые стоит сохранить, лежат в `check/scenarios/`.

```bash
export SHOTS=/tmp/map-shots && mkdir -p "$SHOTS"
cd src
node build.js --only <модули> --out "$SHOTS/<модуль>.html"
node check/drive.mjs "$SHOTS/<модуль>.html" check/scenarios/<сценарий>.mjs 1440x900
```

Сценарий: `export default async (page) => { await page.wait(500); await page.shot('/tmp/map-shots/a.png', {full:true}); }`. Посмотри PNG инструментом Read. `drive.mjs` печатает ошибки консоли.

Для schematic и scene3d, у которых нет своего HTML, в их папке лежит `dev.html`. В сборку он не попадает.

Используй уникальные имена файлов в shots: рядом работают другие модули. Смотри результат глазами, а не только по отсутствию ошибок. Проверяй ширины 1440 и 400, обе темы (`document.documentElement.dataset.theme='dark'`).
